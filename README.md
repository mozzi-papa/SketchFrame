# 윈도우스케치 MVP

현재 활성 창을 화면에 그린 사각형으로 이동하고 크기를 조절하는 macOS 메뉴 막대 앱입니다.

## 실행과 권한

Apple Silicon, macOS 13 이상을 지원합니다. 빌드에는 Xcode 또는 Xcode 명령줄 도구가 필요하며 외부 패키지와 네트워크 연결은 필요하지 않습니다.

1. `build/윈도우스케치.app`을 실행합니다.
2. 메뉴 막대의 점선 사각형 아이콘 → **손쉬운 사용 권한 허용…**을 선택합니다.
3. 시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용에서 **윈도우스케치**를 허용합니다.
4. 메뉴 상태가 **켜짐 · ⌘⇧ 드래그**인지 확인합니다.

앱은 프로젝트의 build 폴더에 있으며 /Applications에 설치하지 않습니다. 로그인 키체인의 **WindowSketch Local Signing** 인증서로 서명합니다. 앱 식별자와 인증서를 유지하여 코드 변경 후에도 같은 앱 식별 규칙을 사용합니다. 이전 임시 서명 버전에서 전환할 때는 손쉬운 사용의 기존 항목을 제거하고 새 앱을 한 번 다시 추가·허용해야 합니다.

인증서나 개인키를 삭제하거나 새 인증서로 교체하면 다시 허용해야 할 수 있습니다. 이 서명은 현재 맥의 로컬 개발용이며 Apple Developer ID 서명과 외부 배포 공증은 포함하지 않습니다.

## 사용 방법

1. 이동할 창을 클릭하여 활성화합니다.
2. `⌘+⇧`를 누른 채 원하는 시작점에서 왼쪽 마우스 버튼으로 드래그합니다.
3. 파란색 미리보기와 px 크기를 확인합니다.
4. 버튼을 놓으면 그린 사각형 그대로 배치를 요청합니다. 드래그 중 `Esc`로 취소할 수 있습니다.

자동 스냅, 최소 크기 확대, 작업 영역에 맞춘 좌표 보정은 없습니다. 시작점과 현재 포인터가 사각형의 두 모서리입니다. 중앙·가장자리·다른 창 근처에서도 같은 규칙을 사용합니다. 너비 또는 높이가 0인 선택만 취소합니다.

대상 앱이 요청한 크기를 허용하지 않으면 **실제로 적용된 크기와 이동 결과를 유지**하고 빨간 경고를 3초 동안 표시합니다. 이전 위치나 크기로 되돌리지 않습니다. 경고는 실제 배치 영역에 표시하며 두 줄로 원인과 크기를 안내합니다.

```text
앱의 최소 크기 제한으로 선택한 영역보다 크게 배치됐습니다.
요청 68 × 92 px · 실제 800 × 600 px
```

위 최소 크기 문구는 앱이 직접 제공한 최소값이 실제 결과를 설명할 때만 사용합니다. 확인되지 않으면 **앱의 크기 제한으로 선택한 영역과 다르게 배치됐습니다.**로 표시합니다. 위치도 요청과 다르면 앱이 허용하는 범위로 배치됐다고 안내합니다. 새 드래그는 이전 안내를 즉시 닫습니다.

드래그 중 앱이 제공하는 최소·최대 크기를 벗어나면 빨간 테두리와 제한 안내를 표시합니다. 같은 창에서 이전에 거부된 동일한 크기도 빨간색으로 경고합니다. 이 기록은 제한의 추정값이 아니며 다른 크기로 확대해서 적용하지 않습니다. 창 내용이 바뀌어 해당 크기를 지원할 수도 있어 경고 상태에서도 놓으면 다시 시도합니다. 요청 크기가 그대로 적용되면 해당 실패 기록을 지웁니다.

사전 정보가 없거나 알려진 제한을 벗어나지 않으면 **놓은 뒤 지원 여부를 확인합니다**라고 표시합니다. 파란색은 지원 확정을 뜻하지 않습니다. 지원 여부는 실제 결과를 읽은 뒤 확정합니다. 창 이동 자체가 거부되거나 결과를 읽을 수 없으면 실패를 안내합니다. 크기 변경을 거부해도 이동이 가능하면 이동 결과와 실제 크기를 유지합니다.

## 동작과 제한

- 영역 아래에 다른 앱이 있어도 드래그 시작 시 활성 앱을 대상으로 유지합니다. 미리보기는 포커스를 가져가지 않습니다.
- 이 조합으로 시작한 드래그는 아래 앱에 전달하지 않습니다. 일반 클릭과 드래그는 그대로 전달합니다.
- 크기는 시작 화면의 `backingScaleFactor`를 반영한 렌더링 픽셀입니다. 529 × 664 논리 좌표는 2배 화면에서 1058 × 1328 px로 표시합니다. 패널의 기본 해상도와는 다를 수 있습니다.
- 실제 결과는 시작 화면의 렌더링 픽셀 단위로 요청과 비교합니다. 사각형 좌표 자체는 반올림하거나 보정하지 않습니다.
- 메뉴 막대나 Dock 근처를 그려도 사각형을 임의로 바꾸지 않습니다. macOS가 위치나 크기를 조정하면 실제 배치를 유지하고 경고합니다. 이동 요청 자체의 오류는 실패로 안내합니다.
- 전체 화면 창, 위치·크기 변경 불가 창, 활성 창이 없는 앱은 지원하지 않습니다.
- shortcut: 미리보기는 드래그를 시작한 화면에 표시합니다. 여러 화면을 가로지르는 표시가 필요할 때 확장합니다.
- shortcut: 적용 결과는 요청 0.4초 뒤 확인합니다. 더 늦게 자체 배치를 변경하는 앱은 추가 관찰이 필요합니다.
- 소개 사이트, 업데이트, 자동 실행, 단축키 변경, 배치 저장은 포함하지 않습니다.

## 데이터와 진단

손쉬운 사용 권한으로 대상 창의 위치·크기를 읽고 변경하며 필요한 전역 입력을 처리합니다. 화면 기록 권한과 서버 통신은 사용하지 않습니다. 스냅 설정 창과 UserDefaults 저장 코드는 제거했습니다. 이전 버전의 저장값을 읽거나 새로 쓰지 않습니다.

미리보기와 글꼴은 입력 연결 전에 준비하고 패널을 재사용합니다. 입력 콜백은 이벤트 가로채기를 결정하며 화면 작업은 반환 후 메인 큐에서 처리합니다. 창 조회·적용은 별도 큐에서 처리합니다. 첫 창 조회의 응답 시간 초과는 한 번 재시도합니다.

메뉴 막대 아이콘 도움말에는 입력 최대 시간, 화면 준비·조회 시간, 시간 초과·재조회 횟수와 최근 취소 사유를 표시합니다. 진단과 이전 창 배치는 작업 중 메모리에서만 사용합니다. 사용자 승인에 따라 거부된 크기는 같은 창의 경고용으로 최대 32개 기록을 메모리에만 유지하고 앱 종료 시 사라집니다. 파일이나 UserDefaults에 저장하지 않습니다.

## 빌드와 검사

최초 한 번만 전용 인증서를 등록합니다. 이 명령은 로그인 키체인에 코드 서명용 인증서와 개인키 한 쌍을 저장하고 현재 사용자의 코드 서명 신뢰를 설정합니다. macOS 인증이 나타나면 직접 처리해 주세요. `codesign`의 개인키 사용 요청에서 **항상 허용**을 선택하면 다음 빌드의 반복 요청을 줄일 수 있습니다. 인증서는 10년 유효하며 기존 유효한 인증서가 있으면 재생성하지 않습니다.

```sh
sh Source/setup-signing.sh
```

개인키 파일과 가져오기용 암호는 제한된 임시 폴더에서만 사용하고 등록 후 삭제합니다. 프로젝트나 앱에는 개인키를 넣지 않습니다. 기존 이름의 인증서가 잘못된 상태이면 자동 교체하지 않고 중단합니다.

일반 빌드는 다음 명령을 사용합니다. 인증서가 없거나 여러 개이면 임시 서명으로 대신하지 않고 중단합니다.

```sh
sh Source/build.sh
build/윈도우스케치.app/Contents/MacOS/WindowSketch --self-test
```

빌드 결과는 `build/윈도우스케치.app`입니다. 빌드 후 최종 경로만 macOS 앱 목록에 등록합니다. 자체 검사는 좌표 보존, 네 방향 드래그, 작은 영역 허용, 잘못된 좌표 거부, 화면 배율, 최소·최대 크기 안내, 창별 실패 기록과 성공 후 삭제를 검사합니다.

서명이 서로 다른 코드에서도 같은 앱 식별 규칙을 유지하는지 검사합니다.

```sh
sh Tests/signing_check.sh
```

이 검사는 임시 폴더에 두 번째 소스 변형을 컴파일해 코드 해시가 다른 두 실행 파일을 만들고, 같은 인증서로 서명하여 식별 규칙의 일치와 상호 검증을 확인합니다. 검사본을 설치하거나 사용자 권한을 변경하지 않습니다. 실제 손쉬운 사용 권한 유지는 새 서명으로 한 번 허용한 뒤 앱을 업데이트하여 별도로 확인합니다.

실제 입력 검사는 [Tests/README.md](Tests/README.md)를 참고해 주세요.
