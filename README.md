# SketchFrame MVP

현재 활성 창을 화면에 그린 사각형으로 이동하고 크기를 조절하는 macOS 메뉴 막대 앱입니다.

## 실행과 권한

Apple Silicon, macOS 13 이상을 지원합니다. 빌드에는 Xcode 또는 Xcode 명령줄 도구가 필요하며 외부 패키지는 필요하지 않습니다. 창 배치는 오프라인에서 동작하며 업데이트 확인·다운로드에는 GitHub 연결이 필요합니다.

1. `build/SketchFrame.app`을 실행합니다.
2. 메뉴 막대의 점선 사각형 아이콘 → **손쉬운 사용 권한 허용…**을 선택합니다.
3. 시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용에서 **SketchFrame**를 허용합니다.
4. 메뉴 상태가 **켜짐 · ⌘⇧ 드래그**인지 확인합니다.

앱은 프로젝트의 build 폴더에 있으며 /Applications에 설치하지 않습니다. 로그인 키체인의 **WindowSketch Local Signing** 인증서로 서명합니다. 앱 식별자와 인증서를 유지하여 코드 변경 후에도 같은 앱 식별 규칙을 사용합니다. 이전 임시 서명 버전에서 전환할 때는 손쉬운 사용의 기존 항목을 제거하고 새 앱을 한 번 다시 추가·허용해야 합니다.

인증서나 개인키를 삭제하거나 새 인증서로 교체하면 다시 허용해야 할 수 있습니다. 이 서명은 현재 맥의 로컬 개발용이며 Apple Developer ID 서명과 외부 배포 공증은 포함하지 않습니다.

## 사용 방법

1. 이동할 창을 클릭하여 활성화합니다.
2. `⌘+⇧`를 누른 채 원하는 시작점에서 왼쪽 마우스 버튼으로 드래그합니다.
3. 파란색 미리보기와 px 크기를 확인합니다.
4. 버튼을 놓으면 그린 사각형 그대로 배치를 요청합니다. 드래그 중 `Esc`로 취소할 수 있습니다.

자유 드래그에는 자동 스냅, 최소 크기 확대, 작업 영역에 맞춘 좌표 보정이 없습니다. 시작점과 현재 포인터가 사각형의 두 모서리입니다. 중앙·가장자리·다른 창 근처에서도 같은 규칙을 사용합니다. 너비 또는 높이가 0인 선택만 취소합니다.

자유 영역 그리기에서 대상 앱이 요청한 크기를 허용하지 않으면 **실제로 적용된 크기와 이동 결과를 유지**하고 빨간 경고를 3초 동안 표시합니다. 이전 위치나 크기로 되돌리지 않습니다. 경고는 실제 배치 영역에 표시하며 두 줄로 원인과 크기를 안내합니다.

```text
앱의 최소 크기 제한으로 선택한 영역보다 크게 배치됐습니다.
요청 68 × 92 px · 실제 800 × 600 px
```

위 최소 크기 문구는 앱이 직접 제공한 최소값이 실제 결과를 설명할 때만 사용합니다. 확인되지 않으면 **앱의 크기 제한으로 선택한 영역과 다르게 배치됐습니다.**로 표시합니다. 실제 적용 결과의 가로·세로 차이가 각각 4 렌더링 px 이내면 미세 차이로 보고 빨간 경고를 띄우지 않습니다. 어느 한쪽이라도 4px를 넘으면 경고합니다. 위치 차이만으로는 경고하지 않습니다. 위치 차이의 원인은 단정하지 않고 진단에 요청·실제 좌표를 남깁니다. 새 드래그는 이전 안내를 즉시 닫습니다.

드래그 중 앱이 제공하는 최소·최대 크기를 벗어나면 빨간 테두리와 제한 안내를 표시합니다. 같은 창에서 이전에 거부된 동일한 크기도 빨간색으로 경고합니다. 이 기록은 제한의 추정값이 아니며 다른 크기로 확대해서 적용하지 않습니다. 창 내용이 바뀌어 해당 크기를 지원할 수도 있어 경고 상태에서도 놓으면 다시 시도합니다. 요청 크기가 그대로 적용되면 해당 실패 기록을 지웁니다.

사전 정보가 없거나 알려진 제한을 벗어나지 않으면 **놓은 뒤 지원 여부를 확인합니다**라고 표시합니다. 파란색은 지원 확정을 뜻하지 않습니다. 지원 여부는 실제 결과를 읽은 뒤 확정합니다. 창 이동 자체가 거부되거나 결과를 읽을 수 없으면 실패를 안내합니다. 크기 변경을 거부해도 이동이 가능하면 이동 결과와 실제 크기를 유지합니다.

## 창 배치와 단축키 설정

메뉴 막대 아이콘 → **설정…**에서 스크린샷의 창 배치 18개와 자유 영역 그리기 조합을 변경할 수 있습니다. 단축키 필드를 선택한 뒤 키를 누르세요. 자유 영역 그리기는 조합키 두 개 이상을 누른 뒤 모두 놓으면 저장됩니다. 기록 중에는 전역 창 배치를 잠시 중지합니다.

`Esc`는 기록 취소, 조합키 없이 `Delete`는 해제입니다. 각 행의 ×로도 해제할 수 있습니다. 중복된 창 배치 키는 저장하지 않으며 **전체 기본값 복원**은 단축키 설정만 초기화합니다. 설정 창은 다른 앱을 선택해도 닫히지 않으며 기록 중이었다면 입력만 취소합니다.

| 동작 | 기본 단축키 |
|---|---|
| 왼쪽·오른쪽·위쪽·아래쪽 절반 | Control + Option + 방향키 |
| 왼쪽 위·오른쪽 위·왼쪽 아래·오른쪽 아래 | Control + Option + U·I·J·K |
| 최대화 | Control + Option + Return |
| 높이 최대화 | Control + Option + Shift + 위쪽 방향키 |
| 작게·크게 | Control + Option + −·= |
| 가운데 | Control + Option + C |
| 복원 | Control + Option + Delete |
| 다음·이전 디스플레이 | Control + Option + Command + 오른쪽·왼쪽 방향키 |
| 가운데 절반·거의 최대화 | 미지정 |
| 자유 영역 그리기 | Command + Shift + 왼쪽 드래그 |

Rectangle과 기본키가 겹치므로 동시에 사용하려면 한쪽 키를 변경하거나 Rectangle을 종료해 주세요. 가운데 절반·거의 최대화는 원하는 키를 지정한 뒤 사용할 수 있습니다. 거의 최대화는 작업 영역의 90%, 작게·크게는 가로·세로 각각 60 렌더링 px씩 변경합니다.

키보드 배치는 해당 디스플레이의 작업 영역을 기준으로 계산합니다. 복원은 앱 실행 중 해당 창에 처음 적용하기 전 배치로 돌아갑니다. 자유 그리기의 실제 결과가 기록된 뒤 사용자가 직접 창을 옮기면 다음 배치의 복원 기준을 갱신합니다. 키보드 배치 뒤에는 결과를 조회하지 않아 외부 이동과 앱의 크기 제한을 구분하지 않으며, 최초 복원 기준을 유지합니다. 기록은 최대 32개이며 앱을 종료하면 사라집니다. 원래 배치가 연결된 화면과 겹치면 그대로 요청하고, 화면 분리로 완전히 벗어났을 때만 현재 화면 안으로 옮깁니다. 다음·이전 디스플레이는 화면 배치 순서로 순환합니다.

키보드 배치는 계산한 위치·크기를 바로 요청합니다. 전체 화면·위치·크기 변경 지원·최소·최대 크기 사전 조회와 적용 후 대기·결과 조회·크기 비교·크기 경고 오버레이를 생략합니다. 대상 창 확인과 계산에 필요한 현재 위치·크기 조회, macOS 변경 요청 자체의 오류 처리는 유지합니다. 메뉴의 **배치 요청 완료**는 요청 전송 완료이며 실제 크기의 일치를 보장하지 않습니다.

## 동작과 제한

- 영역 아래에 다른 앱이 있어도 누를 때 추적 중인 활성 창의 식별자를 고정합니다. 조회나 재시도 중 다른 창으로 바뀌면 선택을 취소합니다. 미리보기는 포커스를 가져가지 않습니다.
- 이 조합으로 시작한 드래그는 아래 앱에 전달하지 않습니다. 일반 클릭과 드래그는 그대로 전달합니다.
- 크기는 시작 화면의 `backingScaleFactor`를 반영한 렌더링 픽셀입니다. 529 × 664 논리 좌표는 2배 화면에서 1058 × 1328 px로 표시합니다. 패널의 기본 해상도와는 다를 수 있습니다.
- 실제 결과는 시작 화면의 렌더링 픽셀 단위로 요청과 비교합니다. 사각형 좌표 자체는 반올림하거나 보정하지 않습니다.
- 메뉴 막대나 Dock 근처를 그려도 사각형을 임의로 바꾸지 않습니다. macOS가 크기를 조정하면 실제 배치를 유지하고 경고합니다. 위치 차이만으로는 빨간 경고를 표시하지 않습니다. 이동 요청 자체의 오류는 실패로 안내합니다.
- 전체 화면 창, 위치·크기 변경 불가 창, 활성 창이 없는 앱은 지원하지 않습니다. 활성 창 변경 알림을 지원하지 않는 앱은 시작 창을 안전하게 확정할 수 없어 선택을 취소합니다.
- shortcut: 미리보기는 드래그를 시작한 화면에 표시합니다. 여러 화면을 가로지르는 표시가 필요할 때 확장합니다.
- shortcut: 자유 영역 그리기의 적용 결과만 요청 0.4초 뒤 확인합니다. 더 늦게 자체 배치를 변경하는 앱은 추가 관찰이 필요합니다.
- 소개 사이트, 자동 실행, 디스크에 창 배치 저장은 포함하지 않습니다.

## 버전과 업데이트

현재 버전은 **0.1.0 (빌드 1)**이며 메뉴 맨 위와 설정창 아래에 실제 번들 값을 표시합니다. 이름은 SketchFrame으로 바뀌었지만 앱 식별자 `personal.windowsketch`, 내부 실행 파일 `WindowSketch`, 기존 서명 인증서와 단축키 저장 키는 유지합니다. 앱 파일은 `build/SketchFrame.app`이며 이전 빌드 파일은 처음 빌드할 때 같은 폴더에서 새 이름으로 옮깁니다.

실행 3초 뒤와 이후 매시간 [SketchFrame GitHub Releases](https://github.com/mozzi-papa/SketchFrame/releases)를 확인합니다. 메뉴와 설정창의 **업데이트 확인…**으로 직접 확인할 수도 있습니다. 새 버전이 있으면 메뉴에 **새 버전으로 업데이트…**, 설정창에 새 버전 안내와 **지금 업데이트…**를 표시합니다. 시스템 알림 권한은 요청하지 않으며 자동 확인이 창 작업을 중단하는 팝업을 띄우지 않습니다.

**지금 업데이트**를 확인하면 ZIP과 SHA-256을 다운로드하고 압축 경로·크기·링크·앱 식별자·버전·서명을 검증합니다. 현재 앱의 인증서 기반 식별 규칙을 만족하는 업데이트만 설치합니다. 준비 파일을 설치 폴더에 두고 기존 앱이 종료된 뒤 교체·재실행합니다. 실패 시 이전 앱 복구를 시도하고 복구까지 실패하면 백업을 보존해 안내합니다. 실행 요청의 성공은 새 앱의 장시간 정상 동작까지 보장하지 않습니다. 설치 폴더에 쓰기 권한이 필요하며 관리자 권한을 자동 요청하지 않습니다.

조회 상태와 시각은 메모리에서만 관리합니다. 네트워크 세션은 디스크 캐시·쿠키·자격 증명 저장을 사용하지 않습니다. 다운로드 임시 폴더는 `SketchFrameUpdate-…`, 설치 준비·백업 폴더는 앱 옆의 `.SketchFrameUpdate-…`이며 정상 완료 또는 복구 성공 후 정리합니다. 단축키 설정은 같은 앱 식별자를 사용해 유지합니다.

릴리스는 `v0.1.0` 같은 정식 태그와 `sketchframe-0.1.0-arm64.zip`, `sketchframe-0.1.0-arm64.zip.sha256` 두 파일이 있어야 감지됩니다. 초안·시험판·다른 주소·체크섬 없는 배포는 제외합니다. 새 버전 배포 시 `Source/Info.plist`의 버전·빌드를 올리고 같은 인증서로 빌드한 뒤 아래 명령으로 배포 파일을 만듭니다. 서명에 사용한 개인키를 저장소나 ZIP에 포함하지 마세요.

```sh
sh Source/package-release.sh
```

GitHub 릴리스 게시는 별도 작업입니다. 첫 릴리스가 아직 없으면 **게시된 정식 업데이트가 없습니다.**라고 안내합니다. 현재 맥의 로컬 서명이며 외부 배포용 Apple Developer ID 서명·공증은 포함하지 않습니다.

## 데이터와 진단

손쉬운 사용 권한으로 대상 창의 위치·크기를 읽고 변경하며 필요한 전역 입력을 처리합니다. 화면 기록 권한은 사용하지 않습니다. 업데이트를 위해 GitHub API와 해당 저장소의 릴리스 파일에 연결합니다. 계정·단축키·창 정보는 전송하지 않으며 조회 요청에 앱 버전만 User-Agent로 포함합니다. 단축키 설정은 UserDefaults의 `shortcutBindings.v1`에 동작별 키 코드·조합키·해제 여부와 저장 형식 정보만 저장합니다. 이전 스냅 설정은 읽거나 쓰지 않습니다.

미리보기와 글꼴은 입력 연결 전에 준비하고 패널을 재사용합니다. 입력 콜백은 이벤트 가로채기를 결정하며 화면 작업은 반환 후 메인 큐에서 처리합니다. 창 조회·적용은 별도 큐에서 처리합니다. 활성 앱의 창 변경 알림으로 대상 창을 미리 추적합니다. 입력 콜백에서는 준비된 창 식별자와 조회 세대만 고정합니다. 준비가 안 됐거나 알림을 지원하지 않으면 안전하게 취소합니다. 확정된 창의 응답 시간 초과는 같은 창만 한 번 재조회합니다. 조회 결과를 받거나 적용하기 전에 대상이 같은지 확인하며 다른 창으로 대체하지 않습니다. 일시적 조회 실패 뒤에는 같은 앱에서도 다시 조회합니다.

입력 상태는 실제 이벤트 연결의 활성 여부를 기준으로 표시합니다. 중단 시 선택을 취소하고 권한·기능 켜짐 상태에 따라 다시 연결합니다. 이미 가로챈 버튼·키가 계속 눌려 있으면 해제까지 소비하고, 중단 중 이미 놓았다면 소비 상태를 지웁니다. 기능 끄기나 권한 철회 상태에서는 자동으로 다시 연결하지 않습니다.

메뉴 막대 아이콘 도움말에는 입력 최대 시간, 화면 준비·조회 시간, 시간 초과·재조회 횟수와 최근 취소 사유를 표시합니다. 자유 그리기의 마지막 요청·실제 사각형의 논리 좌표와 배율을 반영한 위치 차이 px도 확인할 수 있습니다. 키보드 배치는 결과 검사 생략으로 표시합니다. 진단과 이전 창 배치는 작업 중 메모리에서만 사용합니다. 사용자 승인에 따라 거부된 크기는 같은 창의 경고용으로 최대 32개 기록을 메모리에만 유지하고 앱 종료 시 사라집니다. 파일이나 UserDefaults에 저장하지 않습니다.

## 빌드와 검사

최초 한 번만 전용 인증서를 등록합니다. 이 명령은 로그인 키체인에 코드 서명용 인증서와 개인키 한 쌍을 저장하고 현재 사용자의 코드 서명 신뢰를 설정합니다. macOS 인증이 나타나면 직접 처리해 주세요. `codesign`의 개인키 사용 요청에서 **항상 허용**을 선택하면 다음 빌드의 반복 요청을 줄일 수 있습니다. 인증서는 10년 유효하며 기존 유효한 인증서가 있으면 재생성하지 않습니다.

```sh
sh Source/setup-signing.sh
```

개인키 파일과 가져오기용 암호는 제한된 임시 폴더에서만 사용하고 등록 후 삭제합니다. 프로젝트나 앱에는 개인키를 넣지 않습니다. 기존 이름의 인증서가 잘못된 상태이면 자동 교체하지 않고 중단합니다.

일반 빌드는 다음 명령을 사용합니다. 인증서가 없거나 여러 개이면 임시 서명으로 대신하지 않고 중단합니다.

```sh
sh Source/build.sh
build/SketchFrame.app/Contents/MacOS/WindowSketch --self-test
```

빌드 결과는 `build/SketchFrame.app`입니다. 빌드 후 최종 경로만 macOS 앱 목록에 등록합니다. 자체 검사는 좌표 보존, 네 방향 드래그, 작은 영역 허용, 잘못된 좌표 거부, 화면 배율, 최소·최대 크기 안내, 창별 실패 기록과 성공 후 삭제를 검사합니다.

서명이 서로 다른 코드에서도 같은 앱 식별 규칙을 유지하는지 검사합니다.

```sh
sh Tests/signing_check.sh
```

이 검사는 임시 폴더에 두 번째 소스 변형을 컴파일해 코드 해시가 다른 두 실행 파일을 만들고, 같은 인증서로 서명하여 식별 규칙의 일치와 상호 검증을 확인합니다. 검사본을 설치하거나 사용자 권한을 변경하지 않습니다. 실제 손쉬운 사용 권한 유지는 새 서명으로 한 번 허용한 뒤 앱을 업데이트하여 별도로 확인합니다.

실제 입력 검사는 [Tests/README.md](Tests/README.md)를 참고해 주세요.
